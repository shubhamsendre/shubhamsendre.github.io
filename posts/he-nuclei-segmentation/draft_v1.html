What This Is (and Isn’t)

This post is about turning a microscopy image into a measurement table — segment the nuclei in an H&E-stained tissue patch, quantify them (count, area, shape), and score how good that segmentation actually is against expert ground truth.

It is not a diagnostic tool. I’m a bioinformatics engineer, not a pathologist. Everything here is engineering: given a segmentation, how do you honestly measure whether it’s any good, and how much does the choice of method actually matter?

The short answer, with numbers to back it up: a lot.

The Task: Instance Segmentation, Not Just “Find the Nuclei”

Nuclei in a dense tissue patch touch and overlap. The hard part isn’t distinguishing tissue from background — simple intensity thresholding gets you most of the way there. The hard part is separating individual nuclei that are touching, which is what turns this into an instance segmentation problem rather than a semantic one.

That distinction matters for evaluation too. A method can get the foreground region almost perfectly right while still merging a cluster of six nuclei into one blob — which is a serious error for any downstream measurement (cell counts, density, morphology), but invisible to a pixel-accuracy or plain Dice score. So this post scores both.

Two Methods, Scored Honestly

Classical: Otsu threshold → distance transform → watershed. Threshold the image, compute a distance-to-background map, find local maxima as seed points, and let watershed grow regions from those seeds. No training, no learned features — just intensity and geometry.

Deep learning: StarDist, using the pretrained 2D_versatile_he model (trained specifically on H&E-stained nuclei — no fine-tuning done here). StarDist predicts star-convex polygon shapes per nucleus directly, which handles touching nuclei far more gracefully than a purely intensity-driven watershed.

Evaluation: AJI and Panoptic Quality, not pixel accuracy. Aggregated Jaccard Index and Panoptic Quality are instance-aware — they penalize merged and split nuclei, not just boundary disagreement. I also report a plain foreground Dice score for reference, but it’s the weaker signal of the three.

Results on 4 MoNuSeg patches (256×256, held-out test split)

Method AJI Panoptic Quality Dice (foreground)
StarDist 0.655 0.642 0.820
Classical watershed 0.387 0.272 0.638

StarDist wins by a wide margin on every metric, and the gap is largest on Panoptic Quality — exactly the metric most sensitive to merge/split errors. Looking at the per-sample breakdown, the classical baseline’s failure mode is consistent: in dense clusters it over-segments, predicting far more instances than actually exist (92 predicted vs. 39 ground-truth nuclei in one patch) because intensity-based watershed markers proliferate wherever the distance transform has a local wobble. That’s the concrete cost of not learning shape priors.

None of this means classical watershed is useless — with a well-tuned marker distance it’s a legitimate, zero-training baseline for sparse, well-separated nuclei. It just doesn’t hold up on realistic tissue density.

Try It: Interactive Notebook

The comparison above isn’t fixed — you can change the classical baseline’s parameters and watch its score move in real time. The panel below is a full marimo notebook running in your browser via WebAssembly (Pyodide). No server, no Python installation on your end.

One honest caveat on how this is built: StarDist’s segmentation runs on TensorFlow, which cannot execute inside a browser’s WASM sandbox. So the StarDist masks you see below were computed once, offline, and are loaded here as precomputed arrays. The classical watershed baseline, the morphometric plots, and the AJI/PQ/Dice scoring, however, are all genuinely live — scikit-image and SciPy run natively in Pyodide, so moving the slider actually re-segments the image in your browser.

From Masks to Measurements

The point of segmentation, in most real workflows, isn’t the mask itself — it’s what you can measure from it. Once nuclei are labeled, regionprops turns each one into a row of a table: area, perimeter, eccentricity, solidity, centroid. That table is the actual deliverable — it’s what feeds downstream statistics, not the colorful mask image.

This is the throughline of the pipeline: image → instance mask → feature table → validated numbers, with the validation step (AJI/PQ against ground truth) treated as a first-class part of the pipeline rather than an afterthought.

Reproducing This

  • Offline stage (generate_artifacts.py): fetches 4 patches from the MoNuSeg dataset (CC-BY-NC-SA-4.0) via Hugging Face, runs StarDist inference, computes the classical baseline once, scores both against ground truth, and writes the small artifacts this notebook loads. Needs TensorFlow + StarDist — run it in its own environment.
  • Interactive stage (notebook.py): the marimo notebook above. Needs only numpy, pandas, matplotlib, scikit-image, scipy — all WASM-compatible, which is why it can ship as a static page.
# offline (heavy env)
conda run -n nuclei-seg python generate_artifacts.py

# interactive notebook, locally
conda run -n quarto-blog marimo edit notebook.py

# export the interactive layer to a static, browser-runnable bundle
conda run -n quarto-blog marimo export html-wasm notebook.py -o notebook_wasm --mode run
